# Доставка обновлений VERDANT — обязательный порядок

## Основной способ

После первоначальной установки EXE пользователь получает последующие версии внутри запущенного Electron через GitHub Releases репозитория `Dmitrynest2012/VERDANT`. ZIP в чате — только резерв и исходники для VS Code. Нельзя объявлять выпуск доставленным, если готовы только локальные ZIP или коммит main.

## Что делает текущий установленный клиент

Код `electron/main.cjs` проверяет обновления через 9000 мс после запуска, далее каждые `30 * 60 * 1000` мс. Это опрос, не мгновенный push при ответе в чате. При доступном GitHub и новой версии `autoDownload=true` начинает загрузку. По событию update-downloaded показывается нативное окно «Позже / Перезапустить». autoInstallOnAppQuit=false: нельзя обещать установку без подтверждения. В 0.1.10005/0.1.10006 интервал одинаков. Простое повторное открытие приложения запускает раннюю проверку, но не является обязательной ручной переустановкой.

## Выпуск версии

1. Прочитать актуальный main и последний Release. Не затереть новые коммиты владельца, музыку и контент.
2. Перенести исходники завершённой версии; версия увеличивается на один шаг, как 0.1.10005 → 0.1.10006. Не менять appId, origin и ключ сохранения без миграции.
3. Согласовать package.json, HUD, README, CHANGELOG, release-files.json и README текстур. Сохранить Windows CRLF-исправление тестов.
4. Выполнить npm test и сборку Vite. Собрать NSIS-установщик на Windows. Два ZIP должны пройти verify-release.mjs.
5. verify-desktop-release.mjs проверяет имя/версию EXE, его MZ-заголовок, размер, SHA512 относительно latest.yml, blockmap и `win-unpacked/resources/app-update.yml` с provider=github, owner=Dmitrynest2012, repo=VERDANT. Ошибка останавливает публикацию.
6. Создать draft Release с tag v<версия> на проверенный SHA, загрузить все активы, проверить комплект. Только затем снять draft и отметить Latest. Опубликованные версии не перезаписывать; на исправления выпускать следующий номер.
7. После завершения Actions повторно прочитать Releases API: draft=false, prerelease=false, нужный tag и state=uploaded у всех обязательных файлов. Проверить /releases/latest. Только после этого сообщать, что обновление доступно приложению.

## Обязательные файлы релиза

`VERDANT-Setup-<версия>.exe`, соответствующий `.exe.blockmap`, `latest.yml`, `VERDANT_v<версия>_PROJECT.zip`, `VERDANT_v<версия>_TEXTURES_1K.zip`, `SHA256SUMS.txt`.

Контрольные суммы проверяют целостность, но не заменяют цифровую подпись издателя. Текущий установщик не подписан сертификатом. Нельзя называть latest.yml подписанным документом.

## Музыка и сохранения

Владелец загрузил public/audio/relax.mp3 в GitHub. Сохранить этот файл без изменения и включать через Vite public/ в настольный пакет. Не заявлять лицензию трека без подтверждения. MP3 не попадает в маленький архив исходников или PNG-архив. Пользовательские аудиофайлы и сохранения не удалять.

## Честные статусы

Различать: «исходники загружены», «CI собирается», «Release опубликован», «клиент пользователя скачал», «клиент установил». Последние два состояния подтверждаются только на компьютере пользователя, не зелёным CI.

В 0.1.10006 перенесён графический прототип из архива чата: облака — спрайтовые слои, инструмент — CSS/HUD, а не полноценная 3D-модель бура. Качество неба, LOD и плавность карты требуют отдельной визуальной проверки; не объявлять фотореализм и отсутствие багов результатом модульных тестов.
