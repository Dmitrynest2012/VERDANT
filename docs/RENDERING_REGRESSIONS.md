# RENDERING_REGRESSIONS — канон исправлений 0.1.10008

## Граница задачи
Этот выпуск меняет рендер, а не генератор, физику или формат сохранения. generatorVersion 1/2, seed, SurfaceHydrology, FluidWorld и IndexedDB остаются прежними. Исправления применяются к существующим мирам; создавать новый мир ради графики не нужно. WebGPU остаётся основным backend Electron. Новых тяжёлых текстур нет: прежние 14 PNG не изменяются.

## Чёрные треугольники рядом с блоками
На фиксированной сцене seed170621, генератор1, ноги игрока(35.9,7,-4), камера yaw2.4/pitch−.12/FOV78 воспроизведена чёрная треугольная полоса у границы z=0. Она остаётся при отключённых тенях и при unlit override. Луч через пиксель(350,476) изображения1100×720 попадал в far-lod(0,-1,4) на расстоянии около4м вместо травы. Поэтому это не обычная тень и не повреждение сохранения.

Причина: маска вырезала верхние клетки дальнего heightfield около игрока, но НЕ вырезала краевые вертикальные юбки этих клеток. Кроме того, юбки делили нормали с верхом и использовали вырожденные UV(x,z), создавая нулевые tangent. Смена DoubleSide сама по себе не решает проблему.

Исправление: activeCells применяется также к юбкам; вершины юбок независимы, UV развернуты по длине ребра и высоте; неиспользуемые вершины удаляются перед вычислением нормалей, tangent и boundingSphere. Сохранять конечность всех атрибутов, диапазон индексов, ненулевые normal/tangent. В тестовой сцене после исправления луч попадает в section(2,0,0), в землю y=7, а полоса отсутствует на снимке. Не отключать реальные тени ради маскировки дефекта. Очень тёмные боковые грани при низком фоновом освещении — отдельная настройка освещения, не этот геометрический дефект.

## Швы травы
Повороты UV по независимым блокам/кластерам2×2 не гарантировали совместимость краёв. Верхняя трава теперь использует GrassMaterial: непрерывные мировые X/Z, два масштаба одной карты(2.4 и6.7м), поворот второго слоя, плавное смешивание. Normal map проходит ту же трансформацию со скорректированным направлением склонов. Никаких floor(x/z) или случайного UV на границе блока в этом материале. Вершинные AO и крупномасштабный оттенок сохраняются. Боковой дерн остаётся ориентированным вверх. Объёмность блоков и реальные перепады высоты не скрываются.

## Сетка внутри воды
Старая геометрия сравнивала высоту подводной клетки1 с fluidHeight(8)=8/9 соседнего источника и рисовала тонкую внутреннюю стенку на каждом кубе. Между двумя мокрыми соседями поверхность раздела НЕ существует — соответствующие грани запрещены. Полностью погружённая секция не должна иметь поверхностных треугольников.

waterCorner(world,gx,y,gz) детерминированно вычисляет высоту, приближённую глубину и береговую маску по общим соседям вершины. Две секции обязаны получить одинаковые атрибуты на одном стыке. Боковые грани остаются только на настоящей границе воды и воздуха. Нормаль волны аналитическая, коэффициенты согласованы с малой амплитудой displacement. Геометрическая нормаль берётся через normalViewGeometry, не через уже переопределённый normalView. Эти изменения не меняют уровни воды, источники и сохранённые потоки. Кубические ступени дна остаются видимыми через прозрачную воду: это грунт, не внутренняя водяная сетка.

## Обрезанные облака
Нельзя накладывать полупрозрачный shadow fillRect через multiply поверх прозрачного canvas: он добавляет альфу всему прямоугольнику. Использовать source-atop с сохранением исходной alpha, запас вокруг всех пятен и плавное обнуление краёв. Проверка canvas512×512: alpha четырёх краевых полос шириной4px равна0, внутри есть alpha>200. Медленный дрейф привязан к миру, не к перемещению камеры; перенос через дальнюю границу скрывается плавной прозрачностью.

Текущие облака — пространственные группы мягких спрайтов, а не полноценный raymarching. Не называть их фотореалистичным объёмом. В этом выпуске исправляются обрезанные края, а не утверждается законченный атмосферный движок.

## Солнечные блики
SunOptics задаёт3 пятна: тёплое, голубое, розово-фиолетовое. Размеры растут к правому нижнему углу. Конечная точка не равна центру экрана, поэтому при точном взгляде на солнце три пятна не совпадают. Основная прозрачность применяется один раз; прежнее умножение почти нулевой CSS-alpha на почти нулевую opacity делало эффект невидимым.

Проекция использует обновлённую camera.matrixWorld; тест видимости не предполагает один диапазон NDC.z для WebGL/WebGPU. Пятна плавно затухают при отводе взгляда, не видны сквозь твёрдое препятствие, под водой и в меню. Проверка перекрытия — редкий DDA-луч к солнцу, не полный raycast по всем мешам. HUD не перехватывает ввод. Адаптация зрения остаётся мягкой и ограниченной.

## Проверки и границы достоверности
1. npm test: геометрия LOD, конкретный луч на месте треугольника, отсутствие внутренних водяных граней, согласование атрибутов секций, непрерывный материал и расположение бликов.
2. scripts/render-regression.mjs: настоящий Chrome, запуск игры, компиляция TSL-материалов, снимки травы/треугольника/озера/подводного вида, alpha облаков, позиции и прозрачность3 бликов, реальный блок перед солнцем. Использует отдельный временный профиль Playwright, не профиль игрока. На Linux: npx playwright install --with-deps chrome, затем xvfb-run -a npm run test:render.
3. Windows Release: прежние тесты создания мира/именованных слотов/IndexedDB/плавания, сборка Electron, ZIP/CRC/версии и проверка latest.yml/EXE/контрольных сумм, публикация только полного выпуска.

Подготовительная Render Audit проверка 39048326034 прошла на программном WebGL2/Chrome155 и дала изображения без ошибок шейдера. Аппаратный WebGPU и FPS видеокарты пользователя этим не проверены. Попытка WebGPU на Linux CI не смогла создать рабочее устройство; флаги тестовой среды не переносить в Electron и не понижать основной backend ради CI.

Основной способ доставки — опубликованный GitHub Release, а не ZIP из чата. Последний статус проверять в API непосредственно перед ответом пользователю.
