# PROJECT_RULES

## Железные правила проекта VERDANT
1. **Проектный ZIP** всегда маленький и содержит только код, документы, тесты, настройки VS Code и лёгкие служебные файлы.
2. **Контентный ZIP** всегда отдельно и содержит текстуры, карты нормалей, облачные/графические ассеты и прочий тяжёлый контент.
3. Музыка в поставку не входит: пользователь кладёт `public/audio/relax.mp3` сам.
4. Каждая новая сборка увеличивается на **+0.00001**: `0.1.10003 -> 0.1.10004`.
5. Любое крупное техническое решение обязательно фиксируется в `.md`, чтобы следующий чат мог продолжить проект без потери канона.
6. Архитектура мира обязана поддерживать очень большие глубины и большие карты: нельзя делать решения, жёстко завязанные на маленький диапазон `Y`.
7. WebGPU — основной путь. При улучшении графики приоритет: качество + контролируемая производительность.

## Обязательный формат выдачи каждого релиза пользователю
1. **Всегда прикладывать прямые кликабельные ссылки на оба ZIP-архива** в сообщении: `[Скачать VERDANT vX — проект](sandbox:/mnt/data/...)` и `[Скачать VERDANT vX — текстуры/контент](sandbox:/mnt/data/...)`. Одни только пути к файлам без ссылок **запрещены**. Ссылки допустимы только на реально созданные и проверенные файлы текущей рабочей среды.
2. **Красивое, удобное оформление**: отдельный заметный заголовок с номером версии, аккуратный блок загрузок, короткое описание содержимого и размера каждого архива, затем разделы «Что изменилось», «Проверки» и «Как обновить».
3. **Архивы должны быть строго раздельными**: первый — лёгкий ZIP исходников, `.md`-документации, тестов и настроек; второй — ZIP всех необходимых текстур/нормалей и другого тяжёлого контента. Музыку пользователь добавляет самостоятельно.
4. **Не заявлять о проверках, которые фактически не выполнялись**. Отдельно указывать, проверялся ли браузерный запуск WebGPU или только синтаксис/автоматические тесты.
5. **В каждом следующем чате и релизе соблюдать этот формат** независимо от продолжительности разработки. Если ссылка или архив отсутствуют, сначала подготовить/проверить файл, а не заменять ссылку текстовым путём.
6. Наименование пары архивов: `VERDANT_vX_PROJECT.zip` и `VERDANT_vX_TEXTURES_1K.zip` (либо другое единообразное имя с явным указанием формата контента).


## Обязательное качество каждого нового релиза (добавлено v0.1.10004)

- Любой вызов `ui.method()` в `src/main.js` должен иметь реализованный метод `UI.prototype.method` в `src/ui/UI.js`. Нельзя считать релиз готовым после одного лишь синтаксического анализа: запуск проверяется тестом `tests/ui-contract.test.mjs`.
- Автообновление обязано работать при **обычном** `npm run dev`, без второго независимого Vite. `npm run auto:update` может быть равнозначным альтернативным способом запуска. Внутренний сервер — `npm run dev:server`, он не должен создавать ещё один монитор.
- Текстуры и проект поставляются парой ZIP одинаковой версии. Новая установка не запускается до появления обеих частей. Графические ресурсы не помещаются в проектный ZIP, даже в «маленьком» количестве.
- Следует хранить диагностическую команду `npm run update:status` (без побочных эффектов), чтобы быстро определить отсутствующий файл, неправильную папку, устаревший процесс или нераспознанное имя.
- Любое сообщение об успешном `npm test` / `npm run build` / запуске WebGPU разрешено только при фактическом выполнении этой проверки. Если в среде недоступны npm-зависимости, это обязательно объясняется.
- Сохранять совместимость с уже работающими мониторами прошлых версий; не допускать рекурсии при самообновлении `npm run dev`.

## Контроль целостности версии перед публикацией ZIP (релиз 0.1.10004)

- **Недостаточно переименовать архив**: `package.json`, `scripts/release-files.json`, обе отображаемые версии в `index.html`, релизный заголовок `src/main.js`, верхняя строка `README.md`, `public/textures/README.md` и заголовок последнего выпуска в `CHANGELOG.md` должны согласовываться с версией в именах ZIP.
- Перед выдачей пользователю **всегда запускать** `npm test`, затем `node scripts/verify-release.mjs <PROJECT.zip> <TEXTURES.zip>`. Скрипт обязан читать содержимое *уже упакованных* файлов, проверять имена, CRC32, структуру ZIP, версии, манифест и доступность 1K-текстур.
- При переиздании исправленного ZIP **с тем же номером версии** старый монитор, ориентированный на сравнение номеров, может не переустановить PROJECT.zip автоматически. В таком случае пользователю нужна однократная ручная распаковка поверх корня проекта. Об этом обязательно предупредить в инструкции.
- Пара ZIP, их контрольные суммы и размеры проверяются после каждого пересоздания; в проектном ZIP не должно быть PNG, MP3 или личных данных пользователя.

## Канон GitHub и Electron с 0.1.10005
- Официальный источник версий: `https://github.com/Dmitrynest2012/VERDANT/releases`. Изменение кода на `main` НЕ считается готовым обновлением.
- На Windows основной способ — Electron/NSIS с F12 отдельным окном разработчика.
- `npm run dev` в VS Code запускает Vite+Electron, а старый браузерный режим доступен через `npm run dev:browser`.
- GitHub Releases должен содержать Windows Setup, контрольные суммы и отдельные ZIP исходников/контента.
- Сохранения, музыка и пользовательские файлы не удаляются при обновлениях.
