# АВТООБНОВЛЕНИЕ — актуальные правила v0.1.10004

## Повторная выдача исправленного архива с тем же номером v0.1.10004
Если `package.json` уже равен `0.1.10004`, но HUD пишет `0.1.10003`, стандартный монитор может считать проект установленным и **не переустановить** исправленный архив того же номера. Остановите запущенный Vite (`Ctrl+C`), скачайте свежий проектный ZIP (без суффиксов `(1)`), и из корня игры запустите:

```powershell
Expand-Archive -LiteralPath 'D:\Sphere\Titan_3070\user Dmitry Nesterov\Downloads\Downloads_00_All\VERDANT_v0.1.10004_PROJECT.zip' -DestinationPath . -Force
npm run dev
```

Текстуры v0.1.10004 не изменились относительно v0.1.10003; если на экране показано `Нормали 7/7`, повторная ручная распаковка текстур не нужна. После запуска выполните `Ctrl+F5` в браузере. **Не удаляйте** `public/audio/relax.mp3` и сохранения localStorage.


**Если в старой версии обычный `npm run dev` не обновлял ZIP, это было ожидаемо:** он запускал только Vite. С 0.1.10004 `npm run dev` запускает и Vite, и монитор ZIP. Не запускайте два терминала с Vite одновременно.

ВНИМАНИЕ: для первого перехода с 0.1.10003 на 0.1.10004 старый `npm run dev` ещё **не умеет** следить за ZIP. Поэтому:

1. Остановите работающий Vite в VS Code (`Ctrl+C`).
2. Скачайте оба архива 0.1.10004 в `D:\Sphere\Titan_3070\user Dmitry Nesterov\Downloads\Downloads_00_All` с точными именами, без `(1)`.
3. Из **текущей корневой папки игры** выполните `npm run auto:update` — эта команда уже есть в 0.1.10003 и запустит монитор обновления.
4. Дождитесь сообщения `[VERDANT AUTO] Успешно: версия 0.1.10004`; затем обновите браузер `Ctrl+F5`.
5. Начиная с 0.1.10004 в дальнейшем достаточно `npm run dev`. Отдельно `npm run auto:update` больше запоминать необязательно.

**Если в старой версии `npm run auto:update` вообще не стартует**, есть резервный ручной способ:

```powershell
# Команды выполнять в корне проекта VERDANT, в PowerShell VS Code
$zip = 'D:\Sphere\Titan_3070\user Dmitry Nesterov\Downloads\Downloads_00_All\VERDANT_v0.1.10004_PROJECT.zip'
Expand-Archive -LiteralPath $zip -DestinationPath . -Force
# Графику пока не нужно переписывать вручную, если комплект 0.1.10003 уже установлен.
# Для будущих обновлений достаточно запустить новый монитор:
npm run dev
```

Теперь текстурный ZIP можно установить через `npm run dev` даже после ручной распаковки проектного ZIP: расхождение версии в старом `state.json` исправлено. При отсутствии/повреждении прежних текстур распакуйте также `VERDANT_v0.1.10004_TEXTURES_1K.zip` в `public/textures/`. При ручной установке **сначала остановите Vite** и **не удаляйте `public/audio/` или сохранения браузера**.

Диагностика после обновления (в другом терминале VS Code):

```powershell
npm run update:status
```

Она покажет текущую версию, наличие мониторинга, правильный путь Downloads, неподходящие имена и наличие пары ZIP. Сообщение Chrome о `powerPreference` на Windows — предупреждение Chromium, оно не объясняет падение `ui.setGI`.

# VERDANT — автоматическое обновление из ZIP в Windows 11

Релиз механизма: **v0.1.1**, полностью совместим с **v0.1.10002** и последующими пятизначными patch-сборками. Никаких сторонних программ для отслеживания ZIP не требуется: работает `npm run auto:update`, Node.js и VS Code. Сетевой доступ нужен только при необходимости установить/изменить npm-зависимости.

## 1. Каталог и названия архивов

По умолчанию монитор отслеживает:

```text
D:\Sphere\Titan_3070\user Dmitry Nesterov\Downloads\Downloads_00_All
```

Строго распознаваемые имена (патч-счётчик теперь пятизначный, но структура X.Y.Z сохранена):

```text
VERDANT_v0.1.1_PROJECT.zip
VERDANT_v0.1.1_TEXTURES_1K.zip
VERDANT_v0.1.10001_PROJECT.zip
VERDANT_v0.1.10001_TEXTURES_1K.zip
VERDANT_v0.1.10002_PROJECT.zip
VERDANT_v0.1.10002_TEXTURES_1K.zip
...
```

Важное условие: структура любого нового ZIP должна оставаться **полным архивом текущей версии игры**, а не отдельных заменённых файлов. Текстурный ZIP можно размещать позднее проектного; оба архива совместимой версии в одной папке устанавливаются вместе.

### Первоначальное включение автообновления после v0.1.0

1. Остановить работающий вручную `npm run dev` в VS Code (`Ctrl+C`).
2. Распаковать **содержимое** `VERDANT_v0.1.1_PROJECT.zip` в существующую корневую папку проекта VERDANT, где уже расположен `package.json`. Подтвердить замену исходников. **Не создавать вложенную папку** внутри игры.
3. Скопировать **два ZIP v0.1.1** в каталог выше (или установить текстуры самостоятельно, разархивировав `VERDANT_v0.1.1_TEXTURES_1K.zip` прямо в корень проекта).
4. В VS Code в корне проекта открыть терминал и выполнить:

   ```powershell
   npm run auto:update
   ```

   Эта команда сама запустит Vite. Второй `npm run dev` параллельно запускать **не нужно**.
5. Открыть http://127.0.0.1:5173/ и проверить нормали `3/3` на панели. При обновлении открыть/перезагрузить вкладку (Ctrl+F5, если старый JS ещё кэшируется).

Это последний релиз, который нужно один раз распаковать вручную. Последующие ZIP v0.1.10001 и новее достаточно положить в указанный Downloads — при запущенном мониторе произойдёт обновление.

## 2. Автоматический запуск при открытии VS Code

В проекте есть `.vscode/tasks.json`, задача `VERDANT: следить за ZIP и запускать игру` с `runOn: folderOpen`. При открытии рабочей папки VS Code может предложить разрешить автоматические задачи. Дать разрешение для **этой доверенной папки**, иначе запускать через `npm run auto:update` вручную. Задача работает **только пока активна VS Code/терминал** — это не фоновая служба Windows после закрытия редактора.

Новый ZIP определяется `fs.watch` плюс периодическим опросом каталога раз в 4 секунды на случай потери событий Windows. Меняющийся в момент скачивания файл не распаковывается: ждём стабильный размер и время изменения.

## 3. Стадии применения проекта

1. Найти самый новый проектный ZIP по номеру Semantic Versioning (не по времени файла).
2. Дождаться завершения копирования; если есть текстуры той же версии — дождаться обеих.
3. Прочитать ZIP, проверить CRC32, количество, расширения, схему каталогов, версию `package.json`, запрет небезопасных путей, симлинков и архивов-бомб.
4. Сохранить заменяемые файлы для автоматического отката; остановить запущенный Vite.
5. **Распаковать файлы непосредственно в существующий корень проекта** — без вложенных `verdant-voxel-...`. Текстуры — строго в `public/textures/`.
6. Выполнить `npm install` **если поменялись зависимости** или отсутствует `node_modules`; затем `npm test` и `npm run build` для любой принятой поставки.
7. При успехе обновить состояние `.verdant-update/state.json`, сохранить **одну** предыдущую резервную копию `.verdant-update/previous/`, удалить старые отслеживаемые файлы и архивы, запустить Vite заново.
8. При ошибке распаковки / npm / тестов / сборки вернуть предыдущие файлы и снова запустить старую игру. Не считать неисправный релиз установленным.

`npm run auto:update` не является системой безопасного исполнения чужого кода: **не принимайте ZIP от неизвестных отправителей**. Проверка ZIP защищает от повреждения и неправильной распаковки, но не делает произвольный JavaScript безвредным.

## 4. Защита данных и очистка

**Всегда сохраняются:**

- `public/audio/relax.mp3` и другие собственные файлы в `public/audio/`.
- Локальные PNG/JPG/WebP в `public/textures/`, если они не перечислены как управляемые файлы предыдущего успешно установленного текстурного релиза. **Новые texture ZIP могут заменять одноимённые текстуры**, поэтому свои правки лучше хранить дополнительно в отдельной папке.
- `.git/`, `node_modules/` (кроме осознанной работы самого `npm install`), персональные `.env*`, браузерные сохранения `localStorage`.
- Личные ZIP, фотографии, исходники без отметки релиза VERDANT.

**Автоматически очищаются только:**

- В корне игры: файлы из предыдущего сохранённого **манифеста автообновления** (`state.json` либо начальный `scripts/release-files.json`), которые отсутствуют в новом релизе.
- В указанной папке Downloads: ZIP с точными именами `VERDANT_vX.Y.Z_PROJECT.zip` / `VERDANT_vX.Y.Z_TEXTURES_1K.zip`, версия которых **строго меньше успешно установленной**. Текущие ZIP сохраняются. Чужие ZIP не трогаются.
- Более старые резервные копии автообновления; остаётся одна `.verdant-update/previous/`.

Если удалять старые архивы из Downloads не нужно, перед запуском можно задать переменную окружения:

```powershell
$env:VERDANT_CLEANUP_OLD_ARCHIVES = '0'
npm run auto:update
```

Чтобы смотреть другую папку вместо встроенного пути:

```powershell
$env:VERDANT_DOWNLOADS = 'D:\Мои архивы\VERDANT'
npm run auto:update
```

## 5. Ограничения и диагностика

- При отсутствии каталога Downloads игра всё равно запускается; монитор раз в 4 секунды повторяет поиск. Событийный `fs.watch` активируется при старте, когда каталог существует; иначе достаточно периодического опроса.
- Установка ZIP не запускается без работающего `npm run auto:update`/задачи VS Code. Приложение не обновляется, если компьютер выключен.
- При отсутствии VPN новые npm-зависимости могут не установиться. Автообновление откатится и повторит попытку позже; старые зависимости уже установленной игры обычно не скачиваются заново.
- Откат возвращает исходники и текстуры; изменения внутри `node_modules`, которые мог успеть сделать `npm install`, не откатываются автоматически. При необходимости используйте `npm install` ещё раз.
- Если ранее Vite запущен отдельно на 5173, остановите его, иначе второй сервер не стартует (порт зафиксирован; приложение не переключается на случайный порт).
- При ошибках ищите строки `[VERDANT AUTO]` в терминале, при отсутствии нормалей — счётчик `Нормали x/4` в игре.


## 6. Установка v0.1.10001 после v0.1.1

**Ручная распаковка не нужна**, если v0.1.1 уже запускается с `npm run auto:update` (или задачей VS Code). Скопируйте оба новых ZIP в отслеживаемый каталог, дождитесь сообщений `Успешно: версия 0.1.10001`, обновите вкладку `Ctrl+F5`. Новый ZIP контента содержит `public/textures/*.png` — безопасный установщик помещает их именно в `public/textures/`, без лишнего вложенного каталога.

Если монитор не запущен, остановите отдельный Vite и выполните `npm run auto:update`. Текущий `package.json` продолжает поддерживать `npm run dev` для ручной разработки. Версия v0.1.10001 сортируется ВЫШЕ v0.1.1 без изменения кода установщика, поскольку сравнение идёт по числовой тройке компонентов.

Звук `public/audio/relax.mp3` — пользовательский файл, его нет ни в одном ZIP и он не входит в управляемые файлы. Сохранения в браузере на том же `127.0.0.1:5173` сохраняются.

## 7. Релиз v0.1.10002 — новая карта и новые алгоритмы без смены установщика

Имена файлов `VERDANT_v0.1.10002_PROJECT.zip` и `VERDANT_v0.1.10002_TEXTURES_1K.zip`. Монитор из v0.1.1 / v0.1.10001 распознаёт их штатно. ZIP графики повторяет полный набор 9 PNG 1K; новая 3D плотность облаков процедурная и не требует дополнительного ассета. После установки проверить `package.json.version=0.1.10002`, порт 5173, `npm test`, `npm run build`, затем браузер WebGPU. Проектный ZIP не содержит PNG и MP3; пользовательская музыка и localStorage сохраняются.
