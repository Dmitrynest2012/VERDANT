# Канон релизов GitHub — VERDANT

## Источник истины
Репозиторий: `Dmitrynest2012/VERDANT`, ветка `main`. Промежуточные коммиты **не** считаются релизами.

## Публикация
1. Завершить работу и документировать изменения.
2. Прогнать `npm test`, проверить манифест, версию HUD, `package.json`.
3. GitHub Actions на Windows устанавливает зависимости, запускает тесты и Vite build, собирает Electron/NSIS.
4. **Только при успехе** публикует `v0.1.10005` и набор активов: Windows Setup, latest.yml, блокмап, PROJECT.zip, TEXTURES_1K.zip, SHA256SUMS.txt.
5. После публикации приложения увидят новую версию на GitHub Releases. Непроверенный коммит не устанавливается.

## Доступ
На Windows пользователя **не нужен токен**, если репозиторий публичный. GitHub Actions использует встроенный GITHUB_TOKEN; пользователю его никому передавать не нужно.

## Защита от повреждений
- Только semver-версия выше текущей; одинаковые и старые релизы пропускать.
- Скачивать по HTTPS, проверять GitHub SHA-256/контрольные суммы и ZIP-path traversal.
- Для локального dev: резервная копия с откатом при ошибке; пользовательские данные отдельно.
- Для установленного Electron: updater загружает подписанные метаданные/контрольный SHA512 в latest.yml и требует подтверждения перед перезапуском; при отсутствии подписи приложения Windows SmartScreen может предупредить.
- Проверка обновлений не чаще 1 раза каждые 30 минут в установленном Electron, 5 минут в dev.
- Автообновление Electron нельзя считать испытанным до реальной проверки на Windows.
